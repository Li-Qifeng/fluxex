# FluxEx vs Linux.do 客户端功能差距分析

## 一、楼层进度/阅读导航（用户重点指出）

| 功能 | Linux.do | FluxEx 当前 | 差距等级 |
|---|---|---|---|
| **滚动楼层实时检测** | 精确：每个 item 通过 RenderObject/GlobalKey 判断是否在视口 | 粗糙估算：`(offset-300)/120` 固定像素除法 | 🔴 高 |
| **进度条形态** | 右侧竖向 timeline + 进度条，拖拽即可滑动 | 只有数字胶囊，点击弹出输入框 | 🔴 高 |
| **楼层跳转交互** | 拖拽进度条、点击进度条百分比、键盘 J/K | 点击 → AlertDialog 输入数字 → 跳转 | 🔴 高 |
| **楼层列表快速选择** | 楼层列表弹窗（像通讯录索引） | 无 | 🟡 中 |
| **主帖/回复分割线** | 清晰的分割，主帖有独立计数 | 有 Divider 但无独立进度区分 | 🟢 低 |

**修复方案**：
1. 给每个 `ReplyItem` 分配 `GlobalKey`，在 `_onScroll` 中用 `Scrollable.of` + `RenderBox.localToGlobal` 精确判断哪个 reply 的中心点在视口内
2. 楼层进度胶囊改为支持**水平拖拽手势**：`GestureDetector.onHorizontalDragUpdate` 映射到滚动位置
3. 长按时弹出楼层索引列表（1~N 的快速选择器）

## 优先级排序（建议修复顺序）

### 🔴 P0 — 核心体验缺陷
1. **精确滚动楼层检测** — 用 GlobalKey + RenderBox 替代固定像素估算
2. **楼层进度条拖拽交互** — 胶囊支持水平拖拽映射滚动位置
3. **点赞功能** — 帖子/回复点赞（V2EX API 限制，需确认是否有此能力）

### 🟡 P1 — 显著提升交互效率
4. **@用户自动补全** — 输入 `@` 时搜索用户
5. **表情选择器** — 常用 emoji 快速插入
6. **回复一键引用按钮** — 每条回复加「引用」按钮，自动填充 `@user`
7. **列表自动分页加载** — 滚动到底自动加载

### 🟢 P2 — 体验打磨
8. 帖子投票
9. 已读标记
10. 通知分类 Tab
11. 草稿自动保存
